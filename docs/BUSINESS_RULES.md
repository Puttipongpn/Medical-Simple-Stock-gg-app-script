แหล่งข้อกำหนด: [requirements ล่าสุด](../MEDICAL_STOCK_REQUIREMENTS.md), [แผนเดิม](../MEDICAL_STOCK_CODEX_PLAN.md) และ [ขอบเขตเรียบง่ายที่ผู้ใช้ขอล่าสุด](SIMPLE_SCOPE.md)

## Phase 0 ที่ทำในรอบนี้

POC ทดสอบการอ่านและเขียน marker คงที่ในไฟล์ทดสอบ ใช้รหัสทีมบน server ทุก data endpoint แสดงผลอีเมลเท่าที่ Google ให้จริง ไม่มีการสร้าง master หรือ stock

รหัสทีมให้สิทธิ์ทดสอบเท่ากันทุกคน ไม่ใช้การส่งชื่อหรือ role จาก client ให้สิทธิ์เพิ่ม ทุกผู้แก้ Script มีสิทธิ์เข้าถึง config จึงให้เฉพาะผู้ดูแลที่ไว้ใจ ไม่มี credential ผู้ดูแลผ่านเว็บในเฟสนี้; setup รันใน editor ด้วยบัญชีเจ้าของเท่านั้น ฟังก์ชันภายในลงท้าย `_`

`doGet` เป็นข้อยกเว้นเฉพาะหน้าเปล่าสำหรับกรอกรหัส ไม่อ่าน Sheet และไม่ส่งข้อมูล/secret ส่วน runPocCheck, writePocProbe, getPocProbe ตรวจรหัสทุกครั้ง

## กติกาที่ต้องรักษาในเฟสถัดไป (ยังไม่ใช่ฟีเจอร์ที่เสร็จ)

- ยืนยันแล้วว่าเก็บจำนวนรวมตามชนิดอุปกรณ์ ทั้งเครื่องมือแพทย์และวัสดุสิ้นเปลือง ไม่ทำทะเบียนรายเครื่อง และไม่ตีความว่าอุปกรณ์ทุกชนิดใช้แล้วหมด; สมมติฐานอื่นเรื่องคลังเดียว หน่วยหลักเดียว จำนวนเต็ม ปีปฏิทิน หนึ่งชนิดต่อรายการยังต้องยืนยันก่อนข้อมูลจริง
- UUID เป็น ID รหัสอุปกรณ์ไม่ซ้ำ รหัสและเลขอ้างอิงเป็นข้อความรักษาศูนย์นำหน้า
- ผลรวม quantity_delta ของ Movements เป็นยอดคงเหลือ; ห้ามแก้หรือลบ movement
- OPENING ได้ครั้งเดียวต่ออุปกรณ์ ไม่เปิดซ้ำทุกปี RECEIVE/OPENING บวก ISSUE ลบ ADJUST มีเหตุผล REVERSAL ตรงข้ามต้นทางและทำได้ครั้งเดียว
- Server ตรวจสิทธิ์/รูปแบบ แล้วล็อก script เดียว ตรวจ request_id + payload_hash อ่าน master/ยอดล่าสุด ตรวจประวัติ และเขียนแถวเดียว flush ก่อนปลดใน finally
- request_id เดิมและ payload เดิมคืนผลเดิม; payload ต่างปฏิเสธ ผลไม่ชัดเจนต้องสอบถาม/ลองด้วย ID เดิม
- ทุกการเขียนรวม master ใช้ lock เดียวกัน ไม่มี direct Sheet edits หรือ stock-writing trigger
- จำนวนต้องเป็น safe integer ไม่ยอมรับศูนย์/ติดลบในฟอร์มรับจ่าย ไม่รับวันที่อนาคต ไม่ให้ยอดติดลบทุกช่วงประวัติ
- เรียง occurred_date, created_at, movement_id และจำลองย้อนหลังถึงปัจจุบันก่อนรับรายการย้อนหลัง
- ตรวจนับส่ง counted_quantity; server คำนวณส่วนต่างใน lock และให้ยืนยันใหม่เมื่อยอดอ้างอิงเก่า
- REVERSAL ลงวันที่แก้ไข ไม่กลับ REVERSAL ซ้อน ไม่กลับรับเข้าจนยอดติดลบ
- Snapshot รหัส/ชื่อ/หน่วย/หน่วยงาน/ผู้บันทึก; ห้ามเปลี่ยนหน่วยอุปกรณ์ที่มีประวัติ
- ใช้ YYYY-MM-DD สำหรับวันมีผล, Asia/Bangkok ทั้ง Script และ Sheet และส่งวันที่ผ่าน RPC เป็น string
- หยุดเขียนเมื่อ schema/ID/ข้อมูลเสีย ห้ามตีความเป็นศูนย์หรือสำเร็จ
- ป้องกันสูตรใน Sheet/CSV และใช้ textContent/escaping ในเว็บ ปิดใช้งาน master แทนลบ
- ไม่รวมจำนวนข้ามหน่วย รายงานแยก OPENING และ REVERSAL ตรวจยอดต้นงวดข้ามปี

## ทางเลือกการเข้าใช้งานที่เตรียมไว้

POC ใช้ TEAM_ACCESS_CODE เสมอ แม้อ่านอีเมลได้ เพื่อพิสูจน์ทาง fallback โดยไม่สันนิษฐานตัวตน ระบุผลจริงใน ACCESS_TEST_RESULTS ก่อนเลือกวิธีใช้จริง หากอีเมลไม่พร้อมใช้รหัสทีมและเลือก Operators ใน Phase 1/3 โดยชื่อนั้นเป็นการระบุเอง role ไม่ใช่สิทธิ์ที่ยืนยันแล้ว

ยังไม่มีระบบ email allowlist หรือ OAuth เอง ถ้าจะเปลี่ยนเป็น email-based auth ต้องมีหลักฐานสองบัญชีและแก้ contract/test ก่อนใช้ ห้ามลดเป็นเว็บเขียนได้โดยไม่ตรวจ credential
