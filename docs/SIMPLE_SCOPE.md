# ขอบเขตเรียบง่ายสำหรับงานถัดไป

บันทึกตามคำขอล่าสุดของผู้ใช้หลังอ่าน `MEDICAL_STOCK_CODEX_PLAN.md` และ `MEDICAL_STOCK_REQUIREMENTS.md` ฉบับแนบ 6 ตุลาคม 2026 คำขอล่าสุดให้ลดทั้งความซับซ้อนของระบบและกระบวนการพัฒนา รายการในแผนเดิมเป็นข้อมูลประกอบ ไม่ใช่คำสั่งให้ทำทุกเฟสทันที

## สิ่งที่ต้องตอบโจทย์ก่อน

คนในแผนก 7–8 คนเปิดเว็บเพื่อดูว่าอุปกรณ์แต่ละ **ชนิด** เหลือเท่าไร แล้วจดรับเข้า/จ่ายออกได้เร็ว เครื่องมือแพทย์และวัสดุสิ้นเปลืองนับเป็นจำนวนรวมตามชนิด เช่น อัลตราซาวด์ 5 เครื่อง รับเพิ่ม 2 จ่าย 1 เหลือ 6 เครื่อง ไม่มีทะเบียนรายเครื่อง, serial, asset tag หรือผู้ถือครอง

หน้าหลักรุ่นใช้งานแรกให้มีเพียง:

1. รายการอุปกรณ์: รหัสชนิด ชื่อ หน่วยนับ ยอดคงเหลือ และค้นหาง่าย ๆ
2. เพิ่ม/แก้ไขชนิดอุปกรณ์ที่จำเป็นต่อการบันทึก โดยกันรหัสซ้ำ
3. รับเข้าและจ่ายออกทีละชนิด ระบุวันที่ จำนวน และหมายเหตุ/ที่มาหรือผู้เบิกเท่าที่ต้องใช้จริง
4. ประวัติรับ–จ่ายที่อ่านย้อนหลังได้

ยอดเริ่มต้นอาจบันทึกเป็นรายการรับเข้าประเภท “ยอดเริ่มต้น” หนึ่งครั้งต่อชนิดในขั้นใช้งานจริง โดยไม่ต้องมีระบบตรวจนับเต็มรูปแบบก่อนหน้าแรกพร้อมใช้

## วิธีเข้าใช้ที่เรียบง่าย

อัปเดตล่าสุด: ผู้ใช้เลือกให้ stock web app เปิดใช้งานด้วยลิงก์โดยไม่ต้องใช้รหัสทีมชั่วคราว ข้อความด้านล่างเป็นแนวทางเดิมก่อนเปลี่ยนการตัดสินใจนี้; Apps Script deployment ใช้ `ANYONE_ANONYMOUS` และ `USER_DEPLOYING` ผู้มีลิงก์จึงอ่าน/เขียนผ่านเว็บได้

ผู้ใช้ยืนยันภายหลังว่าเปิด POC ได้แล้ว ปัญหา Guest mode ด้านบนเป็นผลเก่า แต่ยังไม่มีผลทดสอบอ่าน/เขียน Sheet จากสองบัญชีจริง

เริ่มจากตัวเลือกที่ deploy ไว้แล้ว: แต่ละคนใช้ **บัญชี Google ส่วนตัวของตนเอง** เปิดเว็บที่ต้อง login, ใช้รหัสร่วมของทีมหนึ่งรหัสสำหรับการอ่าน/เขียน และเลือกชื่อผู้บันทึกเอง ไม่ทำบัญชีผู้ใช้ภายใน ไม่ทำ role/admin UI ไม่ต้องพิสูจน์อีเมลผู้เข้าใช้ หากอีเมลส่วนตัวทำให้ใช้งานจริงไม่ได้ ค่อยทดสอบทางเลือกบัญชี Google เดียวที่ผู้ใช้ยอมรับ โดยไม่สร้างระบบ login เอง

นี่คือการเลือกแนวทางพัฒนาเริ่มต้น ไม่ใช่ผลทดสอบว่าบัญชีที่สองเข้าได้แล้ว การใช้บัญชีเดียวร่วมกันอาจทำให้แยกผู้บันทึกจาก Google ไม่ได้ จึงยังให้เลือกชื่อผู้บันทึกในแบบฟอร์ม

## คงกติกาน้อยข้อที่กันยอดผิด

- บันทึกผ่าน Apps Script เดียวและเก็บรายการเคลื่อนไหวเป็นประวัติ ยอดคงเหลือคำนวณจากรายการ ไม่ให้แก้ยอดตรงใน Sheet
- Server ตรวจอุปกรณ์และจำนวนเต็มบวก รับเข้าบวก จ่ายออกลบ ห้ามจ่ายเกินยอดล่าสุด
- ใช้ script lock ครอบการตรวจยอดกับการเขียน เพื่อกันคนสองคนจ่ายพร้อมกันเกินยอด
- ใช้ request ID กันกดบันทึกซ้ำและช่วยตรวจผลเมื่อเน็ตหลุด
- แสดงข้อผิดพลาดที่เข้าใจง่าย ไม่ตีความข้อมูลเสียเป็นยอดศูนย์

กติกาเหล่านี้ไม่ต้องสร้าง framework หรือขั้นตอนตรวจรับขนาดใหญ่ เขียน tests เฉพาะการคำนวณยอด จ่ายเกิน และการบันทึกซ้ำที่สำคัญ และทดสอบหนึ่งครั้งกับ Google จริง

## เลื่อนไว้หลังหน้าใช้งานหลัก

รายงานเดือน/ปีละเอียด, CSV, แจ้ง stock ต่ำ, ตรวจนับปรับยอด, admin role, backup อัตโนมัติและ restore exercise, การจำลองประวัติย้อนหลังทุกช่วง, และการทดสอบ UI หลายอุปกรณ์อย่างละเอียด เป็นสิ่งที่ requirements เดิมเสนอ แต่ไม่ควรขวางการส่งมอบเครื่องมือรับ–จ่ายและดูยอดชุดแรก การกลับรายการแบบง่ายถูกเพิ่มภายหลังใน version 6 และยังรอผู้ใช้ตรวจบน Google จริง การสำรอง/กู้คืนยังเป็นงานถัดไปก่อนถือว่าพร้อมใช้งานต่อเนื่อง

ยังไม่ทำ: ยืมคืน, เครื่องรายตัว, lot/หมดอายุ, หน่วยย่อย, ต้นทุน, จัดซื้อ, อนุมัติ และเอกสารหลายรายการ

## งานถัดไปที่แนะนำ

1. ปิด POC ที่ deploy แล้วแบบสั้น ๆ: ตั้ง Sheet timezone, Script Properties และรัน setup; เปิดหน้าเว็บด้วยบัญชีเจ้าของและอีกบัญชีหนึ่ง กดอ่าน/เขียน marker ตรวจว่าแต่ละคนใช้งานได้โดยไม่ให้สิทธิ์แก้ Sheet
2. ทำหน้าหลักใช้งานจริงในรอบเดียว: ชนิดอุปกรณ์ + ยอดเริ่มต้น + รับเข้า + จ่ายออก + ยอดคงเหลือ + ประวัติ โดยใช้ไฟล์ทดสอบก่อนข้อมูลจริง
3. ลองกรณีรับ 5 เพิ่ม 2 จ่าย 1 เหลือ 6, จ่ายเกินถูกปฏิเสธ, กดซ้ำไม่เพิ่มรายการ และสองคนจ่ายพร้อมกันไม่ให้ยอดติดลบ แก้สิ่งที่ใช้ไม่สะดวกจากการลองกับผู้ใช้จริง

ผู้ใช้มอบหมายให้เริ่มพัฒนาแล้ว เว็บ stock แยกจาก POC deploy เป็น version 5 และผู้ใช้ลองเพิ่มอุปกรณ์แรก/รับเข้า/จ่ายออกได้แล้ว ยังรอตรวจการเพิ่มชิ้นที่สองหลังแก้ฟอร์มและสรุปรายงานกับ Google จริง ไม่ถือว่าตรวจรับครบ
