# คลังอุปกรณ์การแพทย์

เว็บแอปเล็กสำหรับดูยอดคงเหลือและบันทึกรับเข้า–จ่ายออกของทีม 7–8 คน ใช้ Google Apps Script HTML Service และ Google Sheets ไม่มีเซิร์ฟเวอร์หรือบริการเสียเงินที่ต้องตั้งเพิ่ม

**เริ่มที่นี่:** โค้ดหลักอยู่ในโฟลเดอร์ `src/` บนเครื่องนี้ แก้และทดสอบบนเครื่องก่อน แล้วใช้ `clasp push` ส่งไป Apps Script และ `clasp deploy -i` อัปเดต **deployment เดิม** เว็บที่ผู้ใช้เปิดคือ URL ลงท้าย `/exec`; การแก้ไฟล์หรือกด Save ใน editor อย่างเดียวจะยังไม่เปลี่ยนเว็บนี้

สถานะและผลทดสอบล่าสุดดู [docs/CURRENT_STATE.md](docs/CURRENT_STATE.md) ส่วนแผนงานที่ยังไม่ได้ทำดู [docs/NEXT_STEPS.md](docs/NEXT_STEPS.md)

## ไฟล์ที่แก้เมื่อต้องการเปลี่ยนส่วนต่าง ๆ

| ต้องการแก้ | ไฟล์ |
|---|---|
| ข้อความ ปุ่ม ฟอร์ม และหัวตาราง | `src/StockIndex.html` |
| การทำงานของปุ่ม การเรียก server และการแสดงข้อมูล | `src/StockClient.html` |
| สี ขนาด และการจัดวาง | `src/StockStyles.html` |
| การคำนวณ stock การตรวจข้อมูล รับเข้า จ่ายออก ยกเลิกรายการ และรายงาน | `src/Stock.gs` |
| การเปิดหน้าเว็บและรวมไฟล์ HTML | `src/Main.gs` (`doGet`) |
| การอ่าน Script Properties และข้อความผิดพลาด | `src/Config.gs` |
| การตั้งค่า Apps Script เช่น timezone, สิทธิ์เว็บ และ OAuth scope | `src/appsscript.json` |
| การทดสอบบนเครื่อง | `tests/` |

`Index.html` และ `Client.html` เป็นหน้า POC เก่า ไม่ใช่หน้าคลังที่ `doGet` เปิดอยู่ `Repository.gs` มีฟังก์ชัน script lock และ UUID ที่ระบบ stock ใช้ร่วมด้วย จึงอย่าแก้โดยไม่ตรวจผลกับ stock; `Schema.gs` และ `Setup.gs` เป็นส่วนของ POC เดิม

ถ้าจะเพิ่มความสามารถใหม่ ให้แก้หน้าจอใน `StockIndex.html`, ผูกการทำงานใน `StockClient.html`, เพิ่มหรือตรวจ logic ฝั่ง server ใน `Stock.gs` แล้วเพิ่ม test ใน `tests/` ตามส่วนที่เปลี่ยน ฟังก์ชันใหม่ที่เรียกผ่าน `google.script.run` ต้องเพิ่มชื่อในรายการ public API ของ `scripts/check.cjs`; ฟังก์ชันช่วยภายในให้ลงท้าย `_` อย่าเขียน Google Sheet โดยตรงจาก HTML

ตัวอย่างเปลี่ยนข้อความปุ่ม **Reload Data**: แก้ข้อความระหว่าง `<button id="load">` กับ `</button>` ใน `src/StockIndex.html` โดยคง `id="load"` ไว้ เพราะ JavaScript ใช้ ID นี้ผูกปุ่มกับการโหลดข้อมูล

## ขั้นตอนทำงานบนเครื่อง (วิธีแนะนำ)

ใช้ PowerShell ที่โฟลเดอร์โปรเจกต์นี้ เครื่องที่ใช้ deploy ต้องมี Node.js 20 ขึ้นไป, `npm`, `clasp`, และ login บัญชี Google เจ้าของ Apps Script ไว้แล้ว (`clasp login` หากยังไม่ได้ login) โฟลเดอร์นี้มี `.clasp.json` ชี้โปรเจกต์เดิมอยู่แล้ว; ไฟล์นี้ไม่อยู่ใน Git หากย้ายไปเครื่องอื่น ให้คัดลอก `.clasp.example.json` เป็น `.clasp.json` แล้วใส่ Script ID ของโปรเจกต์ที่ต้องการใช้งาน อย่าสร้าง Script ใหม่โดยไม่ตั้งใจ

```powershell
cd 'C:\Users\Famicon\Documents\ChatGPT\คงคลัง'

# 1) แก้ไฟล์ใน src/ แล้วบันทึก
# 2) ตรวจโค้ดบนเครื่อง (ไม่แตะ Google Sheet)
npm test
npm run check

# 3) ดูว่า clasp จะส่งไฟล์ใดบ้าง
clasp status

# 4) ส่งไฟล์ใน src/ ไปยัง Apps Script HEAD
clasp push --force

# 5) หา deployment ของเว็บ stock ที่ใช้อยู่
clasp deployments

# 6) อัปเดต deployment เดิม: แทนค่า ID ด้วยรายการเว็บ stock จากคำสั่งข้างบน
$deploymentId = 'วาง_DEPLOYMENT_ID_ของเว็บ_stock_เดิม'
clasp deploy -i $deploymentId -d 'อธิบายสิ่งที่แก้สั้น ๆ'

# 7) ตรวจว่า deployment เดิมเป็นเวอร์ชันใหม่
clasp deployments
```

`npm test` ใช้ข้อมูลจำลองและไม่บันทึกข้อมูลจริง; `npm run check` ตรวจ syntax/โครงสร้าง ไม่ต้อง `npm install` สำหรับโปรเจกต์นี้ `clasp push --force` ส่งโค้ด **ทั้งหมดใน `src/`** ไปทับ source บน Google แต่ไม่ล้างข้อมูลใน Sheet จึงต้องแน่ใจก่อนว่าไม่มีคนแก้โค้ดใน Apps Script editor ค้างอยู่ `clasp push` เพียงอย่างเดียวไม่เปลี่ยนเว็บ `/exec`; ต้องทำข้อ 6 ด้วย

**สำคัญ:** ใช้ `-i <DEPLOYMENT_ID>` ของเว็บ stock เดิมเพื่อรักษาลิงก์เดิม อย่ารัน `clasp deploy` แบบไม่มี `-i` หากไม่ได้ตั้งใจสร้างลิงก์ใหม่ เลือก ID จากบรรทัดที่มีคำอธิบาย `Stock MVP ...` ไม่ใช่ deployment POC หรือ `@HEAD` หลัง deploy ให้เปิด URL `/exec` เดิม รีเฟรชหน้า และตรวจการเปลี่ยนแปลงด้วยตนเอง หากเปลี่ยนการคำนวณหรือการบันทึก ให้ทดลองกับข้อมูลทดสอบและตรวจยอด/แถวใน Sheet ด้วย; local tests ไม่พิสูจน์ว่าบริการ Google ทำงานจริง

หากแก้แค่ `README.md`, `docs/` หรือ `tests/` ไม่ต้อง `clasp push` หรือ deploy เพราะไฟล์เหล่านี้ไม่ได้เป็นส่วนของเว็บที่เผยแพร่

## หากต้องการแก้ใน Apps Script editor โดยตรง

ทำได้ แต่ต้องนำการแก้เดียวกันกลับมาไว้ใน `src/` บนเครื่อง **ก่อน `clasp push` ครั้งถัดไป** มิฉะนั้นการ push จะทับงานใน editor

1. เปิด Apps Script editor ของโปรเจกต์เดิม แก้ไฟล์ เช่น `StockIndex.html` และกดบันทึก (`Ctrl+S`) รอจนสถานะบันทึกสำเร็จ
2. กด **การทำให้ใช้งานได้ → จัดการการทำให้ใช้งานได้** เลือก deployment เว็บ stock เดิม แล้วกดรูปดินสอ **แก้ไข**
3. ที่ช่อง **เวอร์ชัน** เลือก **เวอร์ชันใหม่** ใส่คำอธิบาย แล้วกด **ทำให้ใช้งานได้** ตรวจว่า URL `/exec` ยังเป็นลิงก์เดิม
4. เปิดเว็บ `/exec` และรีเฟรชเพื่อตรวจผล จากนั้นคัดลอกการแก้นั้นลงไฟล์ `src/` ที่ตรงกันบนเครื่อง

ถ้าไม่แน่ใจว่าฝั่ง Google กับเครื่องต่างกันตรงไหน ให้หยุดก่อน push และเทียบไฟล์ คำสั่ง `clasp pull` ในโฟลเดอร์โปรเจกต์จะดึง Google HEAD มาทับไฟล์บนเครื่อง จึงไม่ควรรันเพื่อ “ลองดู” โดยไม่สำรองงานที่ยังไม่ได้รวม

## เมื่อ deploy แล้วพบปัญหา

เปิด **การทำให้ใช้งานได้ → จัดการการทำให้ใช้งานได้ → แก้ไข** ของ deployment เว็บ stock เดิม แล้วเลือกเวอร์ชันก่อนหน้าที่ใช้งานได้ กด **ทำให้ใช้งานได้** เพื่อให้ลิงก์เดิมกลับไปใช้โค้ดเวอร์ชันนั้น จากนั้นแก้ต้นเหตุใน `src/` และทดสอบก่อน deploy ใหม่ การสลับเวอร์ชันโค้ดไม่ได้ย้อนข้อมูลใน Sheet; หากเปลี่ยนโครงสร้าง Sheet หรือข้อมูลจริง ต้องตรวจความเข้ากันได้ก่อนย้อนเวอร์ชัน

## กติกาข้อมูลที่ต้องรักษาเมื่อพัฒนาต่อ

- ยอดคงเหลือคำนวณจากแถวใน `Movements` ไม่ใช่ค่าที่ผู้ใช้ส่งมาหรือแก้ตรงใน Sheet; หนึ่งการรับ/จ่าย/ยกเลิกเพิ่ม movement หนึ่งแถว และไม่แก้หรือลบประวัติเดิม
- การเขียนทุกชนิดผ่าน server ภายใต้ script lock เดียวกัน ตรวจยอดไม่ให้ติดลบ และใช้ `request_id` ป้องกันบันทึกซ้ำ
- เว็บ stock ปัจจุบันไม่มีช่องรหัสทีม: ผู้มีลิงก์ `/exec` อ่านและบันทึกผ่านเว็บได้ Deployment ตั้งให้รันในสิทธิ์เจ้าของ (`USER_DEPLOYING`) ไม่ต้องแชร์ Sheet ให้ผู้ใช้แก้ตรง
- ตั้ง `APP_ENV=stock` และ `SPREADSHEET_ID` ใน Apps Script **Script Properties**; ไม่ใส่รหัสผ่าน, OAuth token, Script Properties หรือข้อมูลจริงในโค้ด/Git `TEAM_ACCESS_CODE` เก่าที่อาจยังอยู่ไม่ถูกใช้โดยเว็บ stock
- ก่อนแก้ schema หรือ logic stock ให้สำรอง Google Sheet และทดสอบกับข้อมูลแยกก่อน ห้ามล้างข้อมูลเดิมหรือรัน setup ซ้ำโดยไม่เข้าใจผล
